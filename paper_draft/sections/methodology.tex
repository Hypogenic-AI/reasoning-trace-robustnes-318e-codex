\section{Methodology}
\label{sec:method}

\subsection{Problem Formulation}
\label{sec:formulation}

We study the function $f: \gP \times \gD \rightarrow [0,1]$ mapping a reasoning policy $p \in \gP$ and a dataset $d \in \gD$ to an accuracy score, where $\gP = \{\pnone, \pshort, \pmedium, \plong, \padaptive\}$ and $\gD$ spans an in-distribution (ID) to out-of-distribution (OOD) gradient. We define the \newterm{robustness gap} as
\begin{equation}
\Delta(p) = f(p, d_{\text{ID}}) - f(p, d_{\text{OOD}}),
\end{equation}
where lower values indicate better robustness. We also measure \newterm{token efficiency} $\eta(p) = \text{correct}(p) / \text{tokens}(p)$, the number of correct answers per 1,000 completion tokens.

\subsection{Reasoning Policies}
\label{sec:policies}

We define five prompt-based policies that control reasoning trace length while keeping the underlying model identical:

\begin{enumerate}[leftmargin=*,itemsep=2pt,topsep=2pt]
    \item \textbf{\pnone} (max 100 tokens): The model outputs only a direct final answer with no reasoning.
    \item \textbf{\pshort} (max 300 tokens): At most 1--2 brief reasoning sentences before the answer.
    \item \textbf{\pmedium} (max 800 tokens): Standard chain-of-thought with 4--6 reasoning steps.
    \item \textbf{\plong} (max 2,000 tokens): Detailed reasoning with 8+ steps including self-verification and error checking.
    \item \textbf{\padaptive}: First attempts \pshort reasoning with a self-reported confidence score. If confidence $< 0.70$, retries with \plong reasoning. This tests whether uncertainty-aware escalation can combine the efficiency of short reasoning with the depth of long reasoning.
\end{enumerate}

All policies share an identical answer extraction format (\texttt{ANSWER: <response>}), ensuring that accuracy differences reflect reasoning quality rather than parsing artifacts. We use deterministic decoding (temperature $= 0$) to eliminate sampling variance.

\subsection{Datasets}
\label{sec:datasets}

We select five established benchmarks spanning an ID-to-OOD gradient (\tabref{tab:datasets}). \gsmk serves as the in-distribution anchor: it requires multi-step arithmetic reasoning that aligns well with standard \CoT prompting. \mathfive represents near-OOD transfer (harder math, different problem styles). The three far-OOD datasets (\arcc, \mmlustem, \csqa) test generalization to entirely different reasoning domains---science, STEM knowledge, and commonsense.

\subsection{Evaluation Protocol}
\label{sec:eval}

\para{Answer extraction.} We parse model outputs using regex-based extraction targeting the \texttt{ANSWER:} pattern, with fallback to the last line of the response. Answers are normalized by stripping whitespace, removing formatting artifacts, and applying numeric comparison for mathematical answers.

\para{Metrics.} We report: (1)~\textbf{Accuracy}: exact-match after normalization; (2)~\textbf{Robustness gap}: $\Delta = \text{Acc}_{\text{ID}} - \text{Acc}_{\text{OOD}}$; (3)~\textbf{Token efficiency}: correct answers per 1,000 completion tokens; (4)~\textbf{Calibration}: expected calibration error ($\ece$) and Brier score for the \padaptive policy's self-reported confidence.

\para{Statistical testing.} We use pairwise McNemar tests on shared items with Benjamini-Hochberg correction ($\alpha = 0.05$) for all policy comparisons.

\subsection{Models and Implementation}
\label{sec:models}

Our primary experiment uses \nano (1,250 API calls: 5 policies $\times$ 250 questions). We run a confirmatory experiment on \mini (400 calls: 4 policies $\times$ 100 questions, 20 per dataset) to test whether findings generalize across model sizes. Both models use temperature $= 0$ for deterministic outputs. The evaluation harness is implemented in Python 3.12 with the OpenAI SDK, NumPy, SciPy, Matplotlib, and Seaborn. All outputs are logged to JSONL files with resume-capable deduplication.
